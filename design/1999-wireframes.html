Paper Terminal — a 1999 homepage, modernized

Wireframes only: structure, hierarchy and behavior. No final colour, type or visual polish. The direction takes the signals of a late-90s personal site — catalogues, counters, badges, sidebars, "last updated" — and runs them on modern rails: real status data, accessible navigation, and writing at the centre. The page should read as a working desk, not a résumé.

Three practices, one desk Write / Design / Architect are the navigation and the offer, not a service list. Each has its own archive.
Dense, not crowded 1999 information density with modern spacing and a measured reading column. No decorative emptiness.
Evidence over adjectives Ledgers, dated entries, specs, diagrams and outcomes. Claims are footnotes, not headlines.

What this direction asks of the build

Only three new page types are required: Writing index, Article, and Work/Architect archive. Everything else fits the existing content model.

  • Keep the current serif reading setup; add mono only for metadata, never for body.
  • Reuse data/articles.yaml as the catalogue source; add status, topic, read time, series fields.
  • One 2px rule weight, one ink colour, one accent used only for annotations — no gradients, no shadows except the wireframe's own offset.
  • Badges and counter are static content in v1; wire them to real data later.
  • Semantics first: real heading order, tables for ledgers, aria-current on nav, visible focus rings, reduced-motion for the ticker.

Open questions
